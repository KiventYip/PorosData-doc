# 为 PorosData 文档做贡献

本页说明如何为 `PorosData-doc` 文档站点做贡献。
{: .lead}

如果你要修改运行时代码或处理逻辑，可能需要前往单独的代码仓库。本页只针对当前文档仓库中的内容贡献。

## 你可以贡献什么

外部贡献者可以优先从以下内容开始：

- 优化文案和说明清晰度
- 修复失效链接或导航问题
- 补充示例和参考说明
- 对齐中英文页面内容
- 调整页面结构，让外部读者更容易理解

## 最小文档贡献流程

### 1. 克隆文档仓库

```bash
git clone https://github.com/KiventYip/PorosData-doc.git
cd PorosData-doc
```

### 2. 创建分支

```bash
git checkout -b docs/your-change-name
```

### 3. 修改文档

常见修改包括：

- 编辑 `docs/` 下的 Markdown 页面
- 同步优化中英文内容
- 修复指南页、参考页和研究页之间的跳转关系

### 4. 提交前预览

如果本地环境已准备好，建议先在本地预览文档站点，再发起拉取请求。

至少应检查：

- 页面结构是否清楚
- 标题层级是否合理
- 链接是否可达
- 中英文页面结构是否一致

### 5. 发起 Pull Request

建议在拉取请求中说明：

- 改了什么
- 为什么要改
- 影响了哪些页面
- 如果涉及版式变化，可附上截图

## 写作要求

文档贡献建议遵循以下原则：

- 优先面向外部读者写作
- 优先使用产品视角解释，而不是内部缩写表达
- 中英文同时存在时，尽量保持章节结构一致
- 不要把过时的内部路径、脚本名或临时材料直接写入公开页面

## 推荐切入点

如果你想从较清晰的任务开始，通常可以优先关注：

- 内容偏薄的参考页
- 术语表补充
- 可直接运行的示例页
- 路线图和更新日志的表述优化
- 中英文不一致的问题

## 需要帮助时

如果你发现文档问题或有改进建议，建议直接通过当前文档仓库的 Issue 或 Pull Request 讨论提出。
