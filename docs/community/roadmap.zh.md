# 路线图

本页从对外交付视角说明 PorosData 的路线图，重点回答两个问题：
{: .lead}

- 当前产品今天已经能交付什么
- 最终交付包会如何逐步扩展
{: .tight-list}

## 功能框架

PorosData 围绕一条连续的交付链路组织能力：
{: .section-intro}

| 模块 | 当前角色 | 主要输出 |
|------|------|------|
| `Parser` | 接收原始文献与上游解析结果 | 可继续处理的文本块、图片与基础元数据 |
| `Processor` | 负责质量整理 | 清洗后的中间结果、处理报告、稳定输入 |
| `Designer` | 负责结构化交付 | 全文结果、结构化 JSON、多模态索引 |

这三层不是孤立功能，而是一套面向最终交付的协同框架：先保留原始输入，再稳定内容质量，最后组织成可复用结果。

## 最终交付包

目标交付包包括：
{: .section-intro}

- 按文档编号组织的结果目录
- 面向训练准备的纯文本输出
- 面向抽取、检索和入库的结构化输出
- 保持图文引用关联的多模态索引
- 支持复核与追溯的报告
{: .tight-list}

## 交付时间线

### 阶段一：当前可交付能力

当前阶段重点是让整条流水线具备批量使用能力：
{: .section-intro}

- 从原始文献到最终交付目录的端到端处理
- 全文结果、结构化结果和多模态索引三类核心输出
- 标准化的 `raw -> processed -> structured` 目录模型
- 基础审计、校验和批处理报告支持
- 初步形成 process -> review -> correction -> rerun 的交付闭环
{: .tight-list}

### 阶段二：短期完善方向

短期目标是让输出更稳定，也更容易进入生产项目：
{: .section-intro}

- 进一步统一术语、单位、引文和章节组织
- 提升长文档、复杂公式和大批量任务下的稳定性
- 补充面向外部用户的部署说明、使用说明和结果解读文档
- 强化图文关联与复核工作流
- 逐步固化异常模式反馈与规则更新机制
{: .tight-list}

### 阶段三：最终产品形态

最终目标是形成更完整的科学文献交付产品：
{: .section-intro}

- 更清晰的批量交付标准与结果验收口径
- 围绕全文、结构化和多模态输出的一致交付模型
- 面向训练、抽取、检索和入库的稳定结果复用
- 更好的项目级跟踪、复核与持续迭代
{: .tight-list}

## 适用对象

这份路线图主要面向：
{: .section-intro}

- 准备科研文献数据集的项目团队
- 构建训练语料的工程团队
- 从事结构化抽取和语义检索的应用团队
- 需要可复核交付结果的产品或数据团队
{: .tight-list}
