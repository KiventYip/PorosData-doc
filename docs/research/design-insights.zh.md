为了确保数据能够真正用于大模型训练与科学数据挖掘，PorosData 在数据处理过程中遵循 **AI-Ready 数据处理标准**。该标准关注的不仅是文本的可读性，更强调数据在机器学习环境中的**语义稳定性**、**结构一致性**与**可挖掘性**。

针对不同的 AI 使用场景，数据质量的要求也有所不同。其中最核心的两类应用场景分别为：

- **大模型预训练（Pre-training）**：学习世界知识与语言结构
- **自动化数据挖掘（Data Mining）**：从海量文献中提取结构化知识

# 功能设计

## 1. 数据清洗能力（PorosData Processor）

在大模型预训练阶段，文本数据以 token 序列的形式被模型读取，其核心目标是让模型学习世界知识以及语言结构。如果原始数据中包含错误或噪声，模型便可能在训练过程中形成错误的统计关联，进而影响其对科学概念的理解。因此，AI-Ready 数据在进入预训练流程前必须满足三个基本要求：token 纯净、术语准确以及文本结构连贯。

首先，数据需要保证**token 流的纯净性**。在许多由 PDF 或 OCR 转换而来的文本中，往往会混入与语义无关的字符，例如控制符号、页码索引或格式残留。这些符号并不参与语法结构或语义表达，但在语言模型训练中却会被当作普通 token 处理，从而干扰模型对上下文概率分布的学习。因此，需要对这些非语义字符进行检测与清理，使最终的文本 token 流仅包含与内容相关的信息。

其次，数据需要保证 **科学术语的语义准确性**。科学文献中的术语具有高度稳定的语义结构，如果在文本解析过程中发生系统性误识，模型将学习到错误的知识。例如，在 OCR 处理中，X-ray 可能被误识为 10-ray，这种错误不仅改变了字符形式，还破坏了原有的科学概念。一旦这类错误在训练数据中大量存在，模型在后续任务中就可能无法正确理解与射线衍射相关的科学语境。因此，数据需要通过术语词典与上下文规则确保关键科学概念不会被错误替换。

最后，数据还需要保证 **长文本结构的连贯性**。在 PDF 文档解析过程中，跨行断词与连字符丢失是常见问题。例如 short-range 可能被拆分为 short - range，甚至在换行处被截断为 shortrange。这类结构错误会增加模型词表的不确定性，使本应稳定的术语被拆解为多个无意义 token，从而增加语言建模的复杂度。AI-Ready 数据处理通过修复断词与恢复连字符来保证文本在 token 层面的结构一致性，从而提高模型对复杂长句的理解能力。

## 2. 数据结构化能力（PorosData Designer）

与预训练任务不同，数据挖掘的目标是从海量科学文献中自动提取结构化知识，例如材料成分、实验条件或物理参数。在这一场景下，数据质量的关键不再是语言流畅性，而是**实体识别的稳定性**、**数值表达的准确性**以及**图文信息之间的对齐关系**。

首先，数据需要保证**数值与单位表达的确定性**。科学文献中的关键知识往往以数值形式出现，例如温度、压力或材料参数。然而在 OCR 解析过程中，指数表达式和数字序列常常被错误拆分，例如 $10^5$ 可能被解析为 $1 0 ^ { 5 }$。这种结构破坏会使自动化挖掘算法无法识别正确的数量级，从而导致属性提取失败。因此，AI-Ready 数据处理需要对科学计数法和指数结构进行恢复，使数值表达保持标准化形式。

其次，数据需要保证**实体识别的稳定性**。在材料科学文献中，大量关键信息依赖于化学元素和材料名称，例如 Ni、Au 或 Fe3C。如果这些实体在文本解析过程中被误识为 LaTeX 符号或其他字符结构，例如将 Au 解析为 `\Au`，则后续的实体识别（NER）与实体链接（Entity Linking）都会受到影响，最终导致知识图谱中的实体节点无法正确建立。因此，AI-Ready 数据处理需要通过规则与词典保护关键科学实体，使其在解析与结构化过程中保持一致。

最后，AI-Ready 数据还需要保证**多模态资产的锚定能力**。科学文献中的重要信息往往不仅存在于正文中，还体现在图表与图像数据中。传统文本解析通常只保留“Fig. 1”或“Table 2”这样的字符串引用，但不会建立文本与图像之间的直接关联。AI-Ready 数据处理要求这些引用被转换为可索引的结构化锚点，使文本中的图表引用能够直接定位到对应的图像资产与说明文字（caption）。这种图文之间的结构化连接是实现多模态知识挖掘与科学文档理解的重要基础。

# 功能规划

## 科研数据处理技术路径全景图

### 1. 正则匹配（Regex）：底层「清道夫」

| 维度 | 说明 |
|------|------|
| **核心逻辑** | 基于模式匹配的硬编码规则 |
| **适用场景** | 物理量连词（`3 m m` → `3mm`）、小数点断裂（`0 . 1` → `0.1`）、页码/页眉噪声剔除 |
| **优点** | 速度极快（微秒级）、确定性 100%、不消耗算力 |
| **缺点** | 无法处理歧义。例如 `Ni-` 后面若是换行需连起来，若在句尾可能是负号，正则难以判断 |
| **AI-Ready 贡献** | 初步提升信噪比，减少无意义的 Token 浪费 |

### 2. 词语表挂载（Glossary/Dictionary）：领域知识「防线」

| 维度 | 说明 |
|------|------|
| **核心逻辑** | 利用 Aho-Corasick 等算法进行多模式匹配，将 OCR 碎字符强制对齐到专业术语 |
| **适用场景** | 化学元素（`Z r` → `Zr`）、材料缩写（`B M G` → `BMG`）、专业仪器 |
| **优点** | 极大解决「实体断裂」问题，通过外挂术语表保证核心数据准确性 |
| **缺点** | 维护成本高，对不在词表内的「新材料」或「复合材料」无能为力 |
| **Data Mining 贡献** | 确保实体统一，是构建知识图谱（KG）和属性抽取的核心前提 |

### 3. OCR 模型选配：源头「降维打击」

| 维度 | 说明 |
|------|------|
| **核心逻辑** | 从传统「文字识别」转向「视觉语义理解」 |
| **代表工具** | **传统 OCR**（PaddleOCR、Tesseract）：逐字识别，科学公式和化学符号易崩坏，产生大量 `\mathbf` 噪声；**视觉公式模型**（Nougat、Marker）：针对学术 PDF，不识别单字，直接预测 Markdown/LaTeX 序列 |
| **优点** | 完美还原复杂表格、数学公式和多栏布局 |
| **缺点** | 对算力有要求，非标排版文档可能产生幻觉（如漏段） |
| **AI-Ready 贡献** | 直接输出结构化文本，跳过约 80% 的正则清洗工作 |

### 4. 小模型微调/润色（SLM Finetuning）：语义「终极纠正」

| 维度 | 说明 |
|------|------|
| **核心逻辑** | 利用 1B–3B 规模模型（如 Qwen、Llama），通过 Prompt 或 SFT（指令微调）进行语义纠错 |
| **适用场景** | 处理 `\Delta Nb` 等复杂的、非固定模式的 OCR 伪影 |
| **优点** | 具备「常识」，能推断 Ni 后大概率跟 Nb 而非生僻符号 |
| **缺点** | 速度较慢，需控制不改变原文含义（只改错、不重写） |
| **AI-Ready 贡献** | 将文本质量提升至「接近人类出版物」水平，利于 Embedding 模型的准确索引 |

### 技术方案对比总结

| 方案 | 处理成本 | 灵活性 | 准确度 | 核心目标 |
|------|----------|--------|--------|----------|
| 正则匹配 | 极低 | 低（Hardcode） | 极高（针对模式） | 消除物理噪声（空格、格式） |
| 词表挂载 | 低 | 中（依赖更新） | 100%（词表内） | 实体对齐（材料名、化学式） |
| OCR 选配 | 中/高 | 高 | 高（针对 PDF） | 结构化还原（公式、表格） |
| SLM 微调 | 高 | 极高 | 极高（带语义） | 终极语义纠正 |
