# PorosData-Processor

## 定位

`Processor` 是 PorosData 中负责**数据质量交付**的模块。它不以生成最终数据库结构或知识图谱为目标，而是负责把原始 OCR / MinerU / PDF 解析输出清洗成**清晰、稳定、可读、可计算**的高质量文本，为 `Designer` 提供低噪音、低歧义的输入。

换言之：

- `Processor` 解决“数据是否干净、是否可靠、是否适合进一步处理”
- `Designer` 解决“数据如何被建模、抽取、映射和组织成结构化结果”

## Processor 要交付什么

`Processor` 的最低交付要求包括：

- 消除 OCR 造成的非语义空格、断裂、错字和格式噪音
- 保持材料名、物理量、单位、术语、公式和引用结构的稳定性
- 保护文本中的上下文锚点，避免因清洗破坏实验条件、属性归属和语义关系
- 输出适合 AI 阅读、适合规则匹配、适合后续抽取的统一文本

典型交付对象包括但不限于：

- 正文 `text`
- 图注与图脚注 `image_caption`, `image_footnote`
- 表题与表脚注 `table_caption`, `table_footnote`
- 含行内公式的文字片段
- 后续会进入实体抽取或属性抽取的任何文本字段

## 什么是“就绪”

### AI-Ready

AI-Ready 指文本已经足够干净，可以直接输入 LLM 或 Embedding 模型，而不会因为异常空格、乱码、错位符号或术语误识显著降低模型理解质量。

其核心特征包括：

- 文本足够干净，Token 不被非语义碎片污染
- 语义主体清晰，不因 OCR 断裂而破坏科学概念
- 数值、单位、术语、行内公式保持可读
- 清洗过程不会引入新的歧义

### Data Mining Ready

Data Mining Ready 指文本已经适合作为结构化抽取的输入。

其核心特征包括：

- 实体名称稳定，材料名和术语在文内尽量一致
- 数值、单位和属性可以被规则或模型稳定识别
- 属性与对应值、条件、上下文之间的关系未被破坏
- 文本可以进一步构造为 JSON、表结构、知识图谱或三元组

## 数据质量交付要求

### 1. 文本连续性

必须修复 OCR 造成的非语义断裂，包括但不限于：

- 数字内部空格：`2 0 0` -> `200`
- 小数点断裂：`0 . 5` -> `0.5`
- 数值与单位断裂：`0 . 0 1 0 n m` -> `0.010nm`
- 元素符号断裂：`N i` -> `Ni`
- 非语义换行碎裂：`110 \n s` -> `110s`

### 2. 实体清晰性

必须优先保护和修正以下内容：

- 材料名称
- 化学元素与化合物符号
- 物理量名称
- 实验方法与设备名称
- 领域术语

同一术语在同一文档内不应出现明显影响检索、聚类或识别的混乱写法，例如 `Zr based`、`Zr-based`、`Zr based BMG`。若语义相同，应尽可能输出更一致的写法。

### 3. 数值与单位清晰性

数值与单位必须满足以下要求：

- 数值连续，不允许被 OCR 空格打断
- 小数结构完整，不允许出现分离式小数点
- 指数、上下标、符号尽可能保持正确结构
- 单位采用统一协议，不得在同一语料中混乱输出

### 4. 公式与符号保护

`Processor` 可以修复公式中的 OCR 冗余空格，但必须遵守“修复服从结构安全”的原则：

- 行内公式优先保证结构不损坏
- 显示公式优先保证块级结构不损坏
- 上下标、希腊字母、引用命令与 LaTeX 命令边界必须被保护
- 对无法确认安全的复杂公式，不应做激进改写

### 5. 引文与参考文献结构稳定性

引文规范属于数据质量交付的一部分，而不是附加功能。

- 数字型引文应统一为 `ref[1]`、`ref[2][3]`、`ref[1][2][3]` 等稳定形式
- `[1]`、`[2,3]`、`[1-3]`、`[1, 2, 5-7]` 等混用形式应规整为单一协议
- 引文规范化后不得与前后正文粘连，禁止产生 `wordref[1]` 一类脏数据
- 文末参考文献列表应保留原始条目结构，例如 `[1] Author. Title...`
- 罗马数字等非数字型引用只做括号与空格规范化，不应强行改写为 `ref[...]`

### 6. 元数据字段同样属于质量交付范围

图注、脚注、表题、表脚注虽然不是正文，但同样必须进入清洗范围，因为它们常常包含：

- 图表编号
- 材料名称
- 实验条件
- 单位与数值
- 行内公式
- 结构化抽取的重要上下文

## 文本清洗标准

| 维度 | 处理要求 | 错误示例 (Bad) | 预期输出 (Good) |
|------|----------|----------------|-----------------|
| 物理量聚合 | 数字、小数点、单位之间必须消除非语义空格 | `0 . 0 1 0 n m` | `0.010nm` |
| 化学实体纠错 | 修复断裂的元素符号，匹配领域术语表 | `Z \mathbf{r}`, `N i -` | `Zr`, `Ni` |
| 数值连续性 | 消除数字内部因 OCR 产生的换行或连字符 | `110 \n s` | `110s` |
| 术语一致性 | 同类实体在同一文档内输出尽量一致 | `Zr based`, `Zr-based` | `Zr-based` |
| 引文整洁性 | 数字型引文统一为稳定格式，且不与正文粘连 | `1960 [1]`, `[2,3]`, `[1-3]` | `1960 ref[1]`, `ref[2][3]`, `ref[1][2][3]` |
| 元数据清晰性 | 图注/表题中的数值、单位、实体不应保留明显 OCR 断裂 | `Fig. 1. 1 0 n m` | `Fig. 1. 10nm` |

## 符号与单位协议

### 单位对齐原则

- 采用统一的 `Value + Unit` 表达协议，可为无空格或统一单空格，但项目内不得混用
- 单位写法必须稳定，例如：`mm`、`nm`、`°C`、`s`、`min`、`keV`
- 复合单位、指数单位、公式内单位必须优先保证结构正确，再进行空格修复

### 符号保护原则

清洗过程中必须保护以下结构：

- LaTeX 行内公式
- LaTeX 显示公式
- 上下标
- 希腊字母
- 引用命令与参考文献结构
- 化学元素和单位白名单

## 面向 Designer 的前置条件

为了让 `Designer` 可以稳定开展结构化重构，`Processor` 输出至少应满足：

- 实体名称、实验名、关键术语在文中多次出现时保持高度一致
- 实验条件、温度区间、设备环境等上下文锚点被保留
- 属性与数值、单位保持合理邻近关系，如 `diameter = 3mm`
- 文本中不再保留大量断裂数字、异常空格、不一致术语或损坏公式
- 正文引用与参考文献列表可以被稳定区分

## 禁止破坏项

以下情况属于不可接受的质量回退：

- 将材料名、物理量名、术语误改为其他词
- 破坏公式结构、上下标结构或 LaTeX 边界
- 破坏图注、表题、脚注中的编号信息
- 删除属性与条件之间的关键连接文本
- 误删参考文献列表项
- 将参考文献列表误改写为 `ref[...]`
- 将正文引文与前后正文错误拼接，生成 `wordref[1]` 等脏数据
- 引入新的歧义写法或新的 OCR 噪音
- 只清洗正文而遗漏关键元数据字段

## 质量验收标准

### 交付验收

交付结果至少应满足：

- 无明显 OCR 断裂数字
- 无明显断裂单位
- 无明显术语碎裂
- 无结构性公式损坏
- 无关键元数据字段遗漏处理
- 正文、图注、表题、脚注中的数字型引文已统一为 `ref[n]` / `ref[n][m]...`
- 引文规范化后未与正文粘连，参考文献列表保持 `[n] ...` 原始结构
- 文本适合 AI 阅读与规则处理

### 接入 Designer 的判断标准

只有当以下条件满足时，数据才应进入 `Designer`：

- 文本已经完成基础质量清洗
- 数值、单位、实体具备稳定可识别性
- 图注、表题、脚注等关键字段达到可用状态
- 主要噪音不会显著干扰结构化抽取
- 引文结构已经稳定

### 拒收条件

出现以下任一情况，可判定当前版本不满足要求：

- `Processor` 输出仍存在大量可见 OCR 断裂
- 公式、符号或编号结构被破坏
- 图注、表题、脚注等重要字段未进入质量清洗范围
- 数据虽可阅读，但不具备稳定抽取条件
- 正文数字型引文仍混用多种格式，未统一为单一协议
- 参考文献列表被误改写，或正文起始引文被误判为参考文献条目而漏处理
- 相同类型问题在不同字段上处理标准不一致

## 技术路径说明

本页面约束的是 `Processor` 的**输出质量**，而不是限定具体实现技术。实现可采用以下一种或多种方式：

- 正则规则
- 术语表与白名单
- 结构保护与局部修复
- OCR 后处理策略
- 轻量模型或语义辅助方法

无论采用何种技术路径，最终都必须服务于以下目标：

- `Processor` 负责数据质量交付
- `Designer` 负责数据结构化表达
- 两个包职责分离，但质量链路必须闭环
