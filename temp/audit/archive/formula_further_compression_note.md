## 为何当前不执行

### 1. 下标 / 上标内部（如 `T _ { 2 }`）

- **实现**：`_tighten_subsup_brace_matched` 只对 `_{...}` / `^{...}` 的**内层做 `.strip()`**，不做整段公式修复，也不做“空格+花括号”的语义收紧。
- **原因**：
  - 若对每个 `_{...}` / `^{...}` 的 inner 都调用 `_repair_formula_content`，会**递归进入所有嵌套下标**，深度大时开销和复杂度都上去；
  - 内层可能含 `\text{...}`、`\mathrm{...}` 等，整段 repair 可能改掉不该改的（如文本里的空格）；
  - 括号/花括号校验在内层片段上更容易因边界情况失败，导致整段回退。
- **结论**：为避免递归 repair 的复杂度和误伤，当前刻意**只做 strip，不做下标内部的进一步压缩**。

### 2. `\cfrac`

- **实现**：`_tighten_multiarg_commands` 只处理 `\frac`、`\sqrt`、`\binom`，**没有包含 `\cfrac`**。
- **原因**：历史实现只列了常用命令，`\cfrac` 与 `\frac` 语义相同（双参数），属于遗漏而非有意不收紧。
- **结论**：这里**没有结构性风险**，可以安全地按 `\frac` 一样加入多参收紧。

### 3. `\bigg (` 等

- **实现**：`_tighten_left_right` 只处理 `\left(`、`\right)` 等，**不包含 `\bigg`、`\bigl`、`\bigr`** 等。
- **原因**：同上，未扩展到大括号系列。
- **结论**：扩展到大括号系列（且只做“命令与括号之间空格”的收紧）风险较低，可做。

## 潜在风险（若做“进一步压缩”）

| 做法 | 风险 |
|------|------|
| 对每个 `_{...}` / `^{...}` 内层递归调用 `_repair_formula_content` | 性能、递归深度；内层含 `\text`/特殊结构时可能误改或校验失败导致回退。 |
| 只加“单字母/单数字下标”的局部规则（如 `T _ { 2 }` → `T_{2}`） | 风险较低；需限定模式（如仅 `[A-Za-z]\s+_\s*\{\s*\d+\s*\}`），避免误伤 `x _ { i j }` 等多字符下标。 |
| 将 `\cfrac` 加入 `_tighten_multiarg_commands` | 与 `\frac` 一致，**无明显风险**。 |
| 将 `\bigg`/`\bigl`/`\bigr` 加入类似 `_tighten_left_right` 的收紧 | 仅去掉命令与括号间空格，**风险低**。 |

---

## 建议

1. **建议马上做（低风险）**  
   - 在 `_tighten_multiarg_commands` 中加入 **`\cfrac`**（与 `\frac` 相同，双参数），使 `\cfrac { T } { \Theta }` 等被收紧。

2. **可选、需控范围**  
   - 对下标做**局部**收紧：仅对“单字母 + 空格 + _ + 空格 + { + 数字/单字母 + }”做一次替换（如 `T _ { 2 }` → `T_{2}`），不做整段递归 repair，并加单元测试防止误伤多字符下标。

3. **不建议**  
   - 对任意 `_{...}` / `^{...}` 内层做**完整** `_repair_formula_content` 递归，除非有充分测试和性能评估。

## 五、已实现的进一步压缩（本次已加）

以下低风险压缩已加入代码，重新跑 processor 后会对**新处理的**公式生效：

1. **`\cfrac`**：与 `\frac` 一致，加入 `_tighten_multiarg_commands`，`\cfrac { T } { \Theta }` → `\cfrac{T}{\Theta}`。
2. **`\bigg` / `\big` / `\Big` / `\bigl` / `\bigr` 等**：加入 `_tighten_left_right`，去掉命令与括号间空格，如 `\bigg (` → `\bigg(`。
3. **下标内 “单字母 + 数字”**：新增 `_tighten_subscript_simple_digit`，如 `T _ { 2 }` → `T_{2}`，在 phase1 中与现有步骤一起多轮执行，可处理 `S_{T _ { 2 }}` → `S_{T_{2}}`。

**说明**：含多行的 `\begin{array}` 若整段仍被返回为“未修改”，可能是多行拆分或某格校验导致整段回退，与上述新增规则无关；单格或单行公式（以及正文中的 `$...$` / `$$...$$`）会得到上述进一步压缩。
