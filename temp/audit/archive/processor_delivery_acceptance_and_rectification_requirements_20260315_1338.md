# Processor 交付验收报告与整改要求

> 仓库变更说明（2026-03-17 后）：当前仓库统一批处理入口为 `porosdata-processor` / `python -m porosdata_processor`，`academic_tools/` 已移除，源码仓运行入口保留 `examples/run_pipeline.py`，数据目录已统一为 `data/raw` 与 `data/processed`。本文为历史审计归档，正文若出现旧路径、旧脚本或旧目录命名，均表示审计发生时的仓库状态。

Durantion Time：2603151338

## 1. 文档目的

本报告用于对 `data/raw` 与 `data/processed` 的当前样本处理结果进行正式验收，并形成可直接指导整改的修复清单与复验要求。

本报告面向两类目标：

- **验收判断**：当前 `Processor` 输出是否满足进入 `Designer` 的前置条件。
- **整改执行**：明确哪些问题必须修、按什么优先级修、修到什么程度才算通过复验。

---

## 2. 验收依据

本次验收依据项目标准文档 `docs/ai_ready_and_data_mining_delivery_standard.md`，重点采用以下判定原则：

- `Processor` 必须交付适合 AI 阅读与规则处理的高质量文本。
- 必须消除明显 OCR 断裂数字、断裂单位、术语碎裂。
- 必须保护公式、符号、编号、材料名、数值-单位关系。
- 图注、表题、脚注等关键元数据字段同样属于质量交付范围。
- 若输出仍存在大量可见 OCR 断裂、公式/符号损坏、重要字段未进入清洗范围、或不同字段处理标准不一致，可直接判定为拒收。

## 4. 核查方法

本次验收采用以下方式进行交叉核查：

1. 对照标准文档，提取拒收条件与最低交付门槛。
2. 对每个样本文档逐一比对原始 `*.md` 与处理后的 `*_content_list.json`。
3. 重点核查以下维度：

- 正文文本是否去除了明显 OCR 断裂。
- 材料名、术语、数值、单位是否稳定可识别。
- 公式、LaTeX、符号边界是否被保护。
- 图注、表题、脚注等元数据是否同步清洗。
- 文档内容是否与原始文档一一对应，是否存在错配、串档、测试数据污染。

## 6. 逐样本验收结果

## 6.1 文档 `00005`：内容错配，直接拒收

### 发现

原始文档 `00005.md` 是关于 **amorphous metallic alloys ductile fracture morphology** 的论文；但处理结果 `00005_content_list.json` 中出现的是测试样本文本、测试说明字段和与原文无关的占位数据。

### 具体问题

- 处理结果开头出现 `Tag Structure formation ...`，与原始论文标题完全不符。
- 结果中包含 `description: "测试重点：..."` 等测试说明字段，不应出现在正式交付物中。
- 结果内容包含示例句子、伪造表格标题、演示公式，不属于原始论文。
- 原始文档包含 3 张图片，处理结果对象结构也有 3 个非纯文本对象，但不对应原论文图文内容，且出现了与原文无关的表格对象。

### 判定

此问题属于 **内容映射错误 / 串档 / 测试数据污染**，无论其余规则修复效果如何，都足以单独构成拒收。

### 业务影响

- 下游 `Designer` 会读取错误文档内容。
- 文档级实体抽取、关系抽取、图文绑定将全部失真。
- 后续任何评估结果都不再可信。

---

## 6.2 文档 `00001`：存在实体级错误残留，不满足稳定抽取要求

### 已有改进

`00001` 在数值压缩、部分单位合并、部分 `X-ray` 修复等方面已出现明显改善，说明当前流程不是完全无效。

### 关键问题

尽管有一定修复效果，正文与图注中仍残留会影响语义理解和结构化抽取的实体级错误：

- `Al–In` 被保留为 `Al` 与 `1n` 混杂形式，例如 `Al_{60} 1 n_{40}`。
- `Al_{1-x} In_x` 被保留为 `Al_{1-x} 1n_x`。
- 开头存在可疑的 `Tag ...` 文本条目，不属于论文规范结构。
- 图注字段仍保留明显断裂或未标准化内容。

### 判定

`00001` 未达到以下标准：

- 实体名称稳定；
- 术语可稳定识别；
- 图注等关键元数据达到可用状态；
- 文本适合规则抽取。

因此该样本判定为 **不通过**。

### 业务影响

- 材料体系名称无法稳定归一。
- `Al-In` 相关成分抽取与相图推断会失败。
- 图注中的材料与实验条件无法可靠进入结构化链路。

## 6.3 文档 `00004`：元数据未按同标准清洗，不满足一致性交付要求

### 已有改进

`00004` 正文中的很多数字断裂已被修复，例如：

- `2 5` -> `25`
- `5 0` -> `50`
- `3 1 3` -> `313`
- `2 0 ~ \mathrm { K / m i n }` -> `20 ~ \mathrm{K/min}`

这说明正文文本层已有一定清洗能力。

### 关键问题

图注与正文之间的处理标准明显不一致：

- 正文中的数字空格部分被压缩，但图注中仍保留 `2 5`, `5 0`, `3 1 3` 这类 OCR 断裂。
- 图注中仍保留 `\mathrm { ( P d _ { 3 2 } N i _ { 4 6 } P _ { 2 2 } }` 这类未整理的 LaTeX/实体断裂。
- 正文中某些单位形式已改善，但整体仍存在 `\mathrm{a t .}`、`\mathrm{m l}` 等不稳定表达。

### 判定

`00004` 违反了以下要求：

- 关键元数据字段必须进入质量清洗范围；
- 相同类型问题在不同字段上必须遵循一致的处理标准；
- 图注、表题、脚注达到可用状态后才可进入 `Designer`。

因此该样本判定为 **不通过**。

### 业务影响

- 图文关联抽取会出现字段质量失衡。
- Designer 对正文可识别、对图注不可识别，会造成抽取结果不一致。
- 相同实体在正文与图注中的写法不一致，影响归并与聚类。

## 8. 根因判断

基于当前样本，初步判断问题并非单点缺陷，而是至少同时存在以下几类根因：

### 8.1 输出映射链路缺陷

- 文档 ID 与输出对象的绑定关系可能存在错位。
- 测试样本或调试样本可能混入正式批处理输出目录。
- 批处理时可能存在缓存污染、复用错误或结果覆盖错误。

### 8.2 清洗作用域不完整

- 当前规则可能主要作用于正文 `text`，但未完整覆盖 `image_caption`、`table_caption`、`image_footnote`、`table_footnote`。
- 规则在不同字段上的调用路径不一致。

### 8.3 领域实体修复不足

- 现有规则能够处理部分数字压缩，但无法稳定修复 `Al` / `In`、`Pd` / `Ni`、`X-ray` 等高价值领域实体。
- 对材料名、元素符号、成分表达的白名单/术语表不足。

### 8.4 质量审计与结果统计不足

- 当前处理报告未能反映实际问题。
- 缺少“结果与原文一致性”校验。
- 缺少“元数据字段与正文同标准”校验。

---

## 9. 整改总要求

本次整改必须遵循以下总原则：

1. **先修正确性，再修清洁度。**
  内容错配、串档、测试污染未解决前，不得继续讨论细节清洗优化。
2. **先保一致性，再做局部增强。**
  正文、图注、表题、脚注必须使用同一套质量标准，不允许正文干净、元数据脏乱。
3. **先保证稳定识别，再追求更高压缩率。**
  不能为了压缩空格而破坏实体、公式与单位结构。
4. **修复必须可验证、可回归、可量化。**
  每一类问题都必须对应测试、样本和通过门槛。

## 10. 修复清单要求

## 10.1 P0 必修项：未完成前不得复验

### P0-1 文档内容映射正确性修复

**要求**

- 保证每个输出 `doc_id` 与对应原始文档一一匹配。
- 严禁测试样本、调试样本、示例数据写入正式 `processed_data`。
- 对输出对象建立文档级一致性校验。

**必须达到**

- `00005` 处理结果内容与 `00005.md` 语义一致。
- 标题、作者、章节、图片数量、图注语义与原文相符。
- 输出中不再出现 `测试重点`、示例文本、伪造表格、演示公式等测试痕迹。

**建议实现**

- 在批处理前后增加 `doc_id`、标题片段、对象计数的一致性校验。
- 增加“正式输入目录禁止包含测试模板”的保护。
- 对每个处理结果生成来源摘要并在日志中落盘。

### P0-2 元数据字段统一清洗

**要求**

- `image_caption`
- `image_footnote`
- `table_caption`
- `table_footnote`

以上字段必须与正文 `text` 使用同标准、同优先级的清洗策略。

**必须达到**

- 图注中的数字断裂、单位断裂、术语碎裂得到修复。
- 图注中的材料名、条件、编号可稳定识别。
- 不再出现正文已修复而图注仍保留原始 OCR 断裂的情况。

### P0-3 高价值领域实体保护与修复

**要求**

优先修复并保护以下对象：

- 元素符号：`Al`, `In`, `Ni`, `Pd`, `Zr`, `Cu`, `Nb`, `Y`
- 材料成分表达：如 `Pd42Ni33P25`、`Ni60Nb20Y20`
- 关键术语：`X-ray`, `glass transition`, `supercooled liquid`
- 单位表达：`nm`, `mm`, `K`, `K/min`, `at.%`, `mass%`

**必须达到**

- `Al-In` 不得再出现 `1n` 形式误识别。
- `X-ray` 不得再出现 `10-ray` 或等价漂移。
- `at.%`、`mass%`、`K/min` 等必须稳定输出。

### P0-4 正式结果污染防护

**要求**

- 清理所有测试字段与调试字段。
- 正式交付 JSON 中不得保留 `description`、`测试重点`、调试标签等非交付内容，除非文档协议明确要求。

**必须达到**

- 正式 `*_content_list.json` 仅包含协议允许字段。
- 任何测试样例不得进入生产输出目录。
