# PorosData-Processor 开发状态摘要

**面向管理汇报 | 版本 0.3.0 | 2025-03-04**

---

## 一、核心价值

PorosData-Processor 是**学术文献数据预处理与 Token 优化工具包**，在 AI for Science 数据链路中承担**关键清洗阶段**：

- **输入**：MinerU 解析的 PDF 转 JSON 学术文档
- **输出**：标准化、LLM 可用的文本格式
- **核心作用**：在保护公式、引用等科学结构的前提下，修复 OCR 噪音、规范化 Unicode、压缩空白，从而提升数据质量与 Token 效率

**一句话定位**：将「原始 OCR 输出」转化为「可直接用于训练/推理的高质量文本」的中间件。

## 三、核心风险与阻碍：Shield 边界冲突问题

### 3.1 非技术解释

**问题本质**：系统用「占位符」临时替换公式内容，清洗时只处理占位符外的文本。若占位符的「边界标记」被破坏或与原文冲突，就会出现「边界冲突」——系统无法正确恢复公式，导致部分功能失效。

**通俗比喻**：  
好比把贵重物品装进保险箱后，只对保险箱外的房间做清洁。若清洁过程中误擦了保险箱上的标记，或房间本身就有类似标记，系统就无法区分「哪里是保险箱」——结果要么恢复失败，要么恢复出错。

### 3.2 具体影响

| 影响类型 | 表现 | 对业务的影响 |
|----------|------|--------------|
| **输入碰撞** | 若原文中恰好包含系统保留的边界字符 → 直接报错 | 个别文档无法处理 |

| **流式处理失效** | 公式跨分块时，Shield 无法保护 | 大文档流式处理不可靠，需整篇加载 |

| **边界损坏** | 部分 Pipeline 步骤可能误改占位符边界 | 恢复失败或公式被破坏 |

| **自愈失败** | BoundaryHealer 为启发式修复，成功率有限 | 损坏后可能无法自动恢复 |

### 3.3 技术根因

- Shield 使用 Unicode 边界标记（U+2E28/U+2E29）包裹占位符
- 若输入已含这些字符 → 直接拒绝
- 若 Pipeline 步骤（正则、空白处理等）误改占位符区域 → 恢复时找不到对应关系
- 流式处理按块切分，公式跨块时无法完整保护
